# PENUM: 3 โปรแกรม 1 บ้าน

PENUM PM, PENUM MEP และ PENUM BIM พัฒนา ออกรุ่น และให้เช่าแยกกันได้ แต่ยังอยู่ใน repo เดียวและเว็บเดียว
(fongdabo.github.io/penum) เพื่อให้ทั้ง 3 โปรแกรมในเบราว์เซอร์เดียวกันใช้ข้อมูลร่วมกันได้ทันที
แผนทั้งหมด 4 ขั้นอยู่ในไฟล์โครงการ `penum-split/split-plan.md` เอกสารนี้คือผลของขั้นที่ 1 (จัดบ้าน) ขั้นที่ 2 (แตกไฟล์ PENUM PM เป็นไฟล์ย่อย) และขั้นที่ 3 (รหัสเปิดใช้งานต่อโปรแกรม)

## โครงสร้าง

```
pm/        PENUM PM        src/ (ซอร์สแตกเป็นไฟล์ย่อย ดูหัวข้อถัดไป) + app.json + files/ help/ ที่ขึ้นเว็บคู่กัน
mep/       PENUM MEP       index.html + app.json
bim/       PENUM BIM       index.html + app.json
sales/     ORIEN ฝ่ายขาย   index.html + app.json + icons/ ของตัวเอง
shared/    ของที่ทุกโปรแกรมใช้ร่วม: update.js (ปุ่มอัปเดตโปรแกรม), feedback.js (กล่องแจ้งปัญหา),
           licence.js (รหัสเปิดใช้งานของ MEP และ BIM), files.js (บันทึกโครงการลงโฟลเดอร์ในเครื่อง), sw.js (เปิดแบบออฟไลน์), icons/ (ไอคอน PENUM), landing.html (หน้าแรกของเว็บ)
tools/     สคริปต์: apps.mjs (รายชื่อโปรแกรม), build-pages.mjs (สร้างเว็บ), check-apps.mjs (ตรวจ), src.mjs (รวม/ตัดไฟล์ย่อย),
           sync-feedback.mjs (คัดลอกกล่องแจ้งปัญหาเข้าแต่ละโปรแกรม), SQL ของ Supabase, help/ (ตัวสร้างคู่มือ PM)
```

ที่อยู่บนเว็บไม่เปลี่ยน: `/penum/pm/`, `/penum/mep/`, `/penum/bim/`, `/penum/sales/` และไอคอนยังอยู่ที่ `/penum/icons/`

## ซอร์สของ PENUM PM: `pm/src/`

หน้าโปรแกรม PM คือไฟล์ทุกไฟล์ใน `pm/src/` ต่อกันตามลำดับชื่อ ไม่มี `pm/index.html` ใน repo แล้ว
(ตอนสร้างเว็บ `tools/build-pages.mjs` ต่อให้เอง ผลที่ได้ตรงกับ `pm/index.html` เดิมทุกตัวอักษร)
แต่ละไฟล์คือบรรทัดต่อเนื่องชุดหนึ่งของหน้า ชื่อ `NNN-สิ่งที่อยู่ข้างใน.html|css|js` ตามชนิดของเนื้อหา

| ไฟล์ | เนื้อหา |
|---|---|
| `000-head.html`, `010-style.css`, `020-body.html` | หัวหน้า, CSS หลัก, โครงหน้า และ `<script>` ที่เปิดสคริปต์หลัก |
| `100-core.js` … `910-chat-approvals.js` | ฟีเจอร์ต่าง ๆ เรียงตามลำดับที่เพิ่มเข้ามา (ตาราง แผนงาน จัดซื้อ … แชท) |
| `230-skills-data.js`, `400-thai-address-data.js`, `430-skill-items-data.js`, `640-i18n-en.js` | ข้อมูลก้อนใหญ่บรรทัดเดียว (สกิล ที่อยู่ไทย คำแปลอังกฤษ) อย่าเปิดทั้งไฟล์ |
| `990-start.js` | เริ่มโปรแกรม (load, render) ต้องอยู่ท้ายสคริปต์หลัก |
| `992-feedback.html` | ปิดสคริปต์หลัก, กล่องแจ้งปัญหา และ **เลขรุ่น PM** (`ver:'3.72.1'`) |
| `993-undo.html`, `994-home-button.html` | สคริปต์แยกท้ายหน้า (ย้อนกลับ/ทำซ้ำ, ปุ่มกลับหน้าแรก) |

- ลำดับไฟล์มีผล: ไฟล์หลังมักห่อหรือแทนฟังก์ชันของไฟล์ก่อน (`{const f=render;render=()=>…}`) โค้ดใหม่ต้องอยู่หลังสิ่งที่มันแก้
- **ฟีเจอร์ใหม่ = ไฟล์ใหม่** ตั้งเลขระหว่าง 910 ถึง 990 เช่น `920-ชื่อฟีเจอร์.js` (อยู่ในสคริปต์หลัก ก่อน `990-start.js`)
  ถ้าต้องเป็น `<script>` แยกท้ายหน้า ใช้ `995-….html` ขึ้นไป งานสองชิ้นที่ทำพร้อมกันจึงไม่ชนกัน
- ไฟล์ `.js` ทุกไฟล์ต้อง parse ได้ด้วยตัวเอง (ตัดที่ขอบคำสั่งระดับบนสุด) และบรรทัดแรกของแต่ละไฟล์ต้องไม่ซ้ำกับบรรทัดในไฟล์ก่อนหน้า
  `check-apps.mjs` ตรวจทั้งสองข้อ และบอกชื่อไฟล์กับบรรทัดเมื่อมีข้อผิดพลาด
- หาโค้ด: `grep -rn "ชื่อฟังก์ชัน" pm/src` · ได้หน้าเต็มไว้ดู: `node tools/src.mjs join pm -o /tmp/pm.html`
- เบราว์เซอร์แจ้งข้อผิดพลาดที่ `index.html:5250` → `node tools/src.mjs where pm 5250` บอกว่าอยู่ไฟล์ไหน บรรทัดไหน

### ย้ายงานที่ทำบน `pm/index.html` แบบเดิมมาเป็นไฟล์ย่อย

สำหรับ branch ที่เริ่มก่อนการแตกไฟล์ (เช่น PR #188 ผู้ช่วย AI ที่พักไว้)

```sh
S=$(git rev-list -n 1 origin/main -- pm/index.html)   # commit ที่แตกไฟล์ (ลบ pm/index.html)
git merge $S^                                         # บน branch เดิม: รับ main ถึงก่อนแตกไฟล์ แก้ conflict ในไฟล์เดียวตามปกติ
git show HEAD:pm/index.html > /tmp/old-pm.html        # หน้าเต็มที่มีงานของ branch นี้
git checkout -b <branch-ใหม่> $S                      # เริ่มจากจุดที่แตกไฟล์พอดี
node tools/src.mjs split pm /tmp/old-pm.html          # งานของ branch ลงไฟล์ย่อยที่ถูกต้อง
git add pm/src && git commit -m "port to pm/src" && git merge origin/main
```

ถ้า `split` บอกว่าหาบรรทัดแรกของไฟล์ไหนไม่เจอ แปลว่างานนั้นแก้บรรทัดหัวไฟล์ ให้คืนบรรทัดนั้นแล้วลองใหม่ หรือย้ายส่วนนั้นเอง
งานที่เพิ่ม section ใหม่ท้ายสคริปต์จะไปอยู่ใน `910-chat-approvals.js` ให้ย้ายออกเป็นไฟล์ใหม่ของตัวเอง

## app.json ของแต่ละโปรแกรม

โฟลเดอร์ระดับบนสุดที่มี `app.json` คือโปรแกรมหนึ่งตัว (`tools/apps.mjs` อ่านให้) ไม่ต้องแก้สคริปต์เมื่อเพิ่มโปรแกรมใหม่

| ช่อง | ความหมาย |
|---|---|
| `order` | ลำดับตอนสร้างเว็บ |
| `name`, `short`, `desc`, `theme`, `bg` | ชื่อและสีของแอปที่ติดตั้ง (manifest) |
| `ver` | regex หาเลขรุ่นในซอร์ส ที่ปุ่มอัปเดตโปรแกรมแสดง ถ้าไม่มีใช้วันที่แก้ล่าสุด |
| `save` | คำสั่งบันทึกงานก่อนโหลดรุ่นใหม่ |
| `shim` | แทนบริการดาวน์โหลดของ Artifact ด้วยการดาวน์โหลดของเบราว์เซอร์ (MEP) |
| `ownIcons` | ใช้ `icons/` ในโฟลเดอร์ตัวเองแทนไอคอน PENUM |
| `copy` | ไฟล์เพิ่มเติมที่ขึ้นเว็บคู่กัน `{ที่อยู่บนเว็บ: ไฟล์ต้นทาง}` |
| `links.writes`, `links.reads` | คีย์ที่เก็บข้อมูลร่วมที่โปรแกรมนี้เขียนและอ่าน (ดูหัวข้อถัดไป) |
| `opens` | โปรแกรมที่ปุ่มหัวโปรแกรมเปิดเป็นหน้าต่างแยก |
| `cloud` | `true` = ใส่ `shared/link.js` (รหัสเชื่อมโครงการ เชื่อมข้อมูลข้ามเครื่อง) ลงในหน้า (MEP, PM, BIM) ดูหัวข้อเชื่อมข้ามเครื่อง |
| `team` | `true` = ใส่ `shared/team.js` (โครงการของบริษัท: รายการโครงการรวมของทุกคนในบริษัทเดียวกัน) ลงในหน้า (MEP, BIM) ดูหัวข้อโครงการของบริษัท |
| `files` | `true` = ใส่ `shared/files.js` (บันทึกลงเครื่อง: เก็บแต่ละโครงการเป็นไฟล์ในโฟลเดอร์ PENUM-<โปรแกรม> ที่ลูกค้าเลือกครั้งเดียว ไม่แตะไฟล์อื่นในโฟลเดอร์) ลงในหน้า (MEP, PM, BIM) |
| `fileTypes` | ไฟล์ที่โปรแกรมที่ติดตั้งแล้วเปิดได้ด้วยการดับเบิลคลิก `{ชนิด: [นามสกุล]}` (manifest `file_handlers`, หน้าโปรแกรมรับไฟล์ทาง `launchQueue`) MEP = `.penmep`, PM = `.penpm`, BIM = `.penbim` |
| `licence` | ใส่ `shared/licence.js` ลงในหน้า (MEP, BIM) `keys` = คีย์งานที่หยุดบันทึกเมื่อไม่มีสิทธิ์ (รวม `links.writes` ให้เอง), `work` = คีย์งานที่บอกว่าเครื่องนี้เคยใช้โปรแกรมแล้ว, `sample` = ค่าของงานตัวอย่างที่ไม่นับเป็นงาน (BIM), `skip` = regex ของ hash ที่ไม่ต้องตรวจรหัส (MEP `#v3d=` หน้าดูโมเดล 3 มิติที่แชร์) |

## การเชื่อมข้อมูลระหว่างโปรแกรม

ทั้ง 3 โปรแกรมอยู่เว็บเดียวกัน จึงใช้ `localStorage` ชุดเดียวกันในเบราว์เซอร์เดียวกัน ทุกหน้าต่างเห็นข้อมูลเดียวกัน
และได้ event `storage` เมื่ออีกหน้าต่างเขียน ห้ามเปลี่ยนชื่อคีย์เหล่านี้หรือย้ายโปรแกรมไปคนละโดเมน มิฉะนั้นการเชื่อมจะหยุด

| คีย์ | ผู้เขียน | ผู้อ่าน | เนื้อหา |
|---|---|---|---|
| `penum.mep.link` | MEP (ทุกครั้งที่แก้ไข หน่วง 1.2 วินาที) | PM, BIM | ผลคำนวณ ราคา และ BOQ ของโครงการที่เปิดใน MEP |
| `penum.handoff` | MEP (ปุ่มส่งแบบไป BIM) | BIM (เปิดแล้วลบทิ้ง) | ไฟล์โครงการ BIM รูปแบบ `saoek` ที่ MEP สร้าง (`hid` = เลขของการส่งครั้งนั้น MEP v112 ขึ้นไป, `mepLv` = ระดับชั้นที่เป็นชั้น 1 และ 2 ของ MEP, `mepSeq` = เลข id แรกที่ MEP ใส่ v116 ขึ้นไป) |
| `saoek.v2` | BIM (บันทึกอัตโนมัติ) | MEP | `{"P": โครงการ BIM, "ui": ค่าหน้าจอ}` MEP ใช้ผนังและห้องจาก `P` (`P.mepLid` = รหัสโครงการ MEP ที่เชื่อมไว้ BIM V1.67 ขึ้นไป) |
| `penum.company` | PM (บริษัทที่เปิดอยู่ ทุกครั้งที่หน้าจอวาดใหม่ ยกเว้นบริษัทตัวอย่าง) | MEP, BIM | `{name, en, tax, branch, addr, phone, email, logo}` MEP ใส่ชื่อในช่องบริษัทผู้ออกแบบ / ผู้รับเหมา ของโครงการที่ยังว่าง (ครั้งเดียวต่อโครงการ) BIM ใช้ชื่อ ที่อยู่ โทรศัพท์ และโลโก้ในกรอบชื่อแบบมาตรฐาน |
| `penum.prices` | PM (คลังราคากลางของบริษัทที่เปิดอยู่ หลังแก้ไข 0.6 วินาที ยกเว้นบริษัทตัวอย่าง PM 3.83) | MEP, BIM (รอบ 3 ของ PENUM ราคากลาง) | `{fmt:1, app, co, at, items:[{id, g, name, br, unit, m, l, src, date, key}]}` ราคาไม่รวม VAT `br` ยี่ห้อ / รุ่น (PM 3.84) `m` ค่าวัสดุ `l` ค่าแรงต่อหน่วย `g` หมวด BOQ (`mat` = วัสดุก่อสร้างทั่วไป) `key` = `mep:<คีย์ใน PRICE_DEF ของ MEP>` สำหรับราคาตัวอย่าง |
| `penum.licences` | PM (รหัสของบริษัทที่เปิดอยู่), MEP, BIM (รหัสที่ใส่) | MEP, BIM, PM (หน้าเริ่มใช้งาน) | รหัสเปิดใช้งานในเครื่องนี้ (JSON array ของรหัส `PNM1.…` ลูกค้าละ 1 รหัส ตัวใหม่สุด) ดูหัวข้อรหัสเปิดใช้งาน |

`penum.mep.link` (fmt 1) มีช่อง:
`app` = `'PENUM MEP'`, `fmt` = 1, `project`, `lid` (รหัสเชื่อมโครงการ MEP v106 ขึ้นไป), `date`, `at` (เวลาที่เนื้อหาเปลี่ยนล่าสุด ms จำไว้ข้ามการเปิดใหม่ตั้งแต่ v112),
`bg` (guid ของโครงการ BIM ที่ MEP นำตัวอาคารมา ถ้ามี v116 ขึ้นไป), `design {to, twb, ti, rh, sf}`, `loads {tr, rooms[{id, name, room, pn, area, btu, tr, cmh, sys, qty, size}]}`,
`boq {sub, ohp, vat, grand, items[{g, group, head, type, desc, unit, q, m, l, pm, pl, total}]}`, `prices`
PM ใช้ `project`, `boq.items` (ดึง BOQ เข้าโครงการ ใบเสนอราคา และงานประมูล) และ `loads.rooms` (ลมออกแบบรายห้อง)
BIM จับคู่ `loads.rooms` กับห้อง: `id` (ห้องใน MEP) ตรงกับ `e.mep.id` ของห้องที่ MEP สร้างหรือส่งผลไปให้, `pn` (ห้องใน BIM ที่ MEP นำเข้ามา
ใช้เมื่อ `bg` ตรงกับ `P.guid`), แล้วจึงชื่อห้อง (`room` = ชื่อที่ไม่มีรหัสเครื่องนำหน้าและ (ชั้น N) ต่อท้าย เทียบทั้งแบบมีและไม่มีเลขห้อง) (v116, BIM V1.69)

ในเบราว์เซอร์เดียวกันเห็นเฉพาะโครงการที่เปิดล่าสุดใน MEP/BIM ข้ามเครื่องและโครงการอื่นใช้รหัสเชื่อมโครงการ (หัวข้อถัดไป)

### เชื่อมข้ามเครื่อง (รหัสเชื่อมโครงการ)

- ทุกโครงการใน PENUM MEP มีรหัสของตัวเอง (`P.lid` ตัวอักษร Crockford base32 20 ตัว แสดงเป็น `XXXXX-XXXXX-XXXXX-XXXXX`)
  โครงการใหม่ได้รหัสใหม่ เปิดไฟล์โครงการเดิมได้รหัสเดิม
- MEP ส่งข้อมูลชุดเดียวกับ `penum.mep.link` ขึ้น Supabase ของ ORIEN หลังแก้ไขล่าสุด 5 วินาที (เฉพาะเมื่อเนื้อหาเปลี่ยน ไม่ส่งตอนไม่มีสิทธิ์ใช้งาน)
  ช่อง `mep` ของตาราง `penum_link` (`tools/link-setup.sql` รันครั้งเดียว rpc `penum_link_put`, `penum_link_get`, `penum_link_at` ใช้กุญแจสาธารณะ)
  แถวหาด้วย sha256('penum-link:' + รหัส) 16 ไบต์แรก และเข้ารหัส AES-GCM ด้วย sha256('penum-link-key:' + รหัส) ORIEN อ่านไม่ได้
  `penum.mep.sent` จำต่อรหัสว่าเนื้อหาล่าสุดคืออะไร เปลี่ยนเมื่อไร และส่งขึ้นคลาวด์แล้วหรือยัง (v112) เปิด MEP ใหม่โดยไม่แก้ไขจึงไม่ส่งซ้ำ
  โครงการตัวอย่างที่ยังไม่ได้แก้ไขไม่ส่งเอง (`P.smp` = ลายนิ้วมือของผลคำนวณตอนเปิดตัวอย่าง) จะส่งเมื่อแก้ไขหรือกดปุ่มคัดลอก
  ปุ่มคัดลอกลิงก์/รหัสถามคลาวด์ก่อน ถ้าแถวหายไปจะส่งใหม่
- หน้า BOQ ของ MEP มีการ์ด "ส่ง BOQ ให้ PENUM PM เครื่องอื่น" (รหัส + ลิงก์ `…/pm/#mep=<รหัส>`)
- PENUM PM เก็บโครงการ MEP ที่เชื่อมไว้ใน `P.mep {code, name}` (ข้อมูลโครงการ จึงไปกับคลาวด์/OneDrive ของ PM ด้วย) เชื่อมได้ 3 ทาง:
  กดดึง BOQ จาก MEP ในเบราว์เซอร์เดียวกัน, เปิดลิงก์ `#mep=` (ถามว่าเข้าโครงการไหน), หรือ ใส่รหัสเชื่อมจาก PENUM MEP
  ถ้า MEP ในเบราว์เซอร์นี้เปิดโครงการนั้นอยู่ใช้ `penum.mep.link` ไม่อย่างนั้นใช้ข้อมูลจากคลาวด์ (ถามเมื่อเปิดหน้า ข้อมูลโครงการและ BOQ
  และเมื่อกลับมาที่หน้าต่าง ไม่เกินทุก 1 นาที) `P.boq.mepSig` จำ BOQ ที่ดึงไว้ เพื่อบอกว่า MEP แก้ไขหลังดึงครั้งล่าสุด
- PENUM BIM (V1.67) เก็บรหัสโครงการ MEP ที่เชื่อมไว้ใน `P.mepLid` (`''` = ผู้ใช้กดเลิกเชื่อม จะไม่เชื่อมเองอีก) โครงการที่ MEP สร้าง
  (มี `P.mepLink.lid`) เชื่อมเอง เชื่อมได้อีก 2 ทาง: ลิงก์ `…/bim/#mep=<รหัส>` จากการ์ด "เชื่อมต่อกับ PENUM BIM" ในแท็บแบบ 3D ของ MEP
  (ถามว่าเชื่อมโครงการที่เปิดอยู่ เริ่มโครงการใหม่ชื่อเดียวกับ MEP หรือเปิดแบบที่ MEP ส่งมา ถ้าเปิดบ้านตัวอย่างอยู่ให้เริ่มโครงการใหม่อย่างเดียว
  ถ้ายังไม่มีรหัสเปิดใช้งานจะถามหลังใส่รหัส) หรือ เมนู › เชื่อมกับโครงการใน PENUM MEP แล้ววางรหัส
  - ผลคำนวณ: ถ้า MEP ในเบราว์เซอร์นี้เปิดโครงการนั้นอยู่ใช้ `penum.mep.link` ไม่อย่างนั้นใช้ช่อง `mep` จากคลาวด์ (ถามเมื่อเปิดโครงการ
    เมื่อกลับมาที่หน้าต่างไม่เกินทุก 1 นาที และเมื่อเปิดผลคำนวณ) บอกว่าอัปเดตเมื่อเนื้อหาเปลี่ยนเท่านั้น
  - แบบ: BIM ส่งโครงการ (ข้อความเดียวกับ `P` ใน `saoek.v2`) ขึ้นช่อง `bim` 8 วินาทีหลังบันทึก เฉพาะเมื่อต่างจากที่ส่งครั้งล่าสุด
    MEP ใช้ช่องนี้เมื่อ `saoek.v2` ในเบราว์เซอร์เดียวกันไม่ได้เชื่อมกับโครงการนี้ (โครงการ BIM ที่เชื่อมกับโครงการ MEP อื่นจะไม่ถูกนำมาแสดง)
  - ส่งแบบไป BIM: MEP เขียน `penum.handoff` และช่อง `hand` (มี `hid`) BIM ที่เชื่อมรหัสนั้นไว้ถามครั้งเดียว
    ถ้ามีโครงการ BIM ที่มีผนังแล้ว (โครงการที่ MEP นำตัวอาคารมา `P.cad.imp[f].g/lv`, ไม่อย่างนั้นโครงการที่เชื่อมกับโครงการนี้ ไม่อย่างนั้นไฟล์ที่เปิดไว้ที่นำเข้าแบบ)
    MEP ส่งโครงการนั้นตามที่ BIM มีอยู่ตอนนี้ แทนที่เฉพาะงานระบบที่ MEP วาดในระดับชั้น `mepLv` ปุ่มเป็น "ส่งงานระบบไปที่ PENUM BIM" (MEP v116, BIM V1.69)
    BIM ที่เปิดโครงการเดียวกัน (`guid` ตรงกัน) ถาม "รับงานระบบ" แล้วรวมเข้าโครงการที่เปิดอยู่ (`mepMerge` ย้อนกลับได้ในครั้งเดียว): ลบงานระบบแบบที่ MEP วาด
    ในระดับชั้นนั้น ใส่ของที่ MEP ส่งมา (id ใหม่) ห้องเดิมได้ `e.mep` ใหม่ ห้องที่ MEP เพิ่มเข้ามา ตัวอาคารและสิ่งที่แก้ใน BIM หลัง MEP ดึงไปจึงไม่หาย
    ไม่มีโครงการแบบนั้นหรือ BIM เปิดโครงการอื่นอยู่ จะถามให้เปิดแบบจาก MEP แทนโครงการที่เปิดอยู่ (แบบเดิม)
  - `penum.bim.link` = `{ids: hid ที่ตอบแล้ว 30 ตัวล่าสุด, at: {รหัส: เวลาช่อง hand ที่เห็นแล้ว}, sent: {รหัส: ลายนิ้วมือที่ส่งล่าสุด}}`
  - โครงการ MEP หนึ่งควรเชื่อมกับโครงการ BIM เดียว ถ้าเชื่อม 2 เครื่อง ช่อง `bim` เป็นของเครื่องที่บันทึกล่าสุด

### เชื่อมด้วยไฟล์ เมื่อไม่มีอินเทอร์เน็ต (MEP v118, PM 3.86, BIM V1.71)

ใช้ไฟล์ที่มีอยู่แล้ว ไม่มีรูปแบบไฟล์ใหม่: ไฟล์โครงการ `.penmep` ของ MEP (`shared/files.js`) และไฟล์สำหรับ PENUM BIM

- MEP ใส่ `mepLink` (ข้อมูลชุดเดียวกับ `penum.mep.link` มี `lid` และ `at`) ในไฟล์ `.penmep` ทุกไฟล์ที่บันทึก (`pnFileText`
  โครงการที่ไม่ได้เปิดอยู่ใช้ `pnLinkOf`) และใน `J.mepLink` ของไฟล์สำหรับ BIM เปิดไฟล์ `.penmep` ใน MEP แล้ว `ensure()` ลบ `mepLink`
  ทิ้งและคำนวณใหม่จากตัวโครงการ ปุ่มบันทึกไฟล์: หน้า BOQ การ์ดส่ง BOQ ให้ PENUM PM › "บันทึกไฟล์โครงการ (.penmep)"
  (เป็นปุ่มหลักเมื่อส่งขึ้นคลาวด์ไม่ได้ `pnCBad`) และ บันทึกลงเครื่อง ในหน้ารวมโครงการ
- ไฟล์สำหรับ PENUM BIM (แท็บแบบ 3D การ์ด "ส่งไป PENUM BIM"): ถ้ามีโครงการ BIM ที่ตัวอาคารมาจาก (`pnSrc` ตัวเดียวกับการส่งสด)
  ปุ่มหลักคือ "สร้างไฟล์งานระบบสำหรับ PENUM BIM" (ชื่อไฟล์ `… - งานระบบ PENUM BIM.json`) อีกปุ่มสร้างไฟล์โครงการใหม่ทั้งไฟล์
- PM: หน้า ข้อมูลโครงการและ BOQ › "เปิดไฟล์จาก PENUM MEP" รับ `.penmep` หรือไฟล์สำหรับ BIM (`window.pmMepFile(txt, name)`)
  แล้วถามว่าเข้าโครงการไหน เหมือนลิงก์ `#mep=` ข้อมูลจากไฟล์จำไว้เฉพาะหน้าต่างนั้น (`MF`) PM ใช้ตัวที่ `at` ใหม่สุดระหว่าง
  `penum.mep.link`, คลาวด์ และไฟล์ ไฟล์ `.penmep` จาก MEP ก่อน v118 ไม่มี `mepLink` PM บอกให้บันทึกไฟล์ใหม่
- BIM: ไฟล์ › เปิดไฟล์งาน… หรือลากไฟล์มาวาง (`window.bimFileIn(txt, name)`) แยกตามชนิดไฟล์:
  - `.penmep`: รับผลคำนวณ (`P.mepLink`) และเชื่อมโครงการที่เปิดอยู่ (`P.mepLid`) ย้อนกลับได้ ถ้าเชื่อมกับโครงการ MEP อื่นอยู่ถามก่อน
    บ้านตัวอย่างได้โครงการใหม่ชื่อเดียวกับ MEP
  - ไฟล์งานระบบ (มี `mepLv`): ถามเหมือนรับงานระบบ (รับเฉพาะงานระบบ หรือ เปิดทั้งไฟล์แทน) แล้วเชื่อมรหัสจาก `J.mepLink`
  - ไฟล์โครงการที่ MEP สร้าง (มี `hid` หรือ `mepSeq`): เปิดเหมือนส่งแบบ ไฟล์อื่นเปิดแบบเดิม
  - `P.mepLink` จากไฟล์ใช้แทนข้อมูลคลาวด์เมื่อ `at` ใหม่กว่า
- กล่องเชื่อมทุกที่บอกวิธีใช้ไฟล์เมื่อไม่มีอินเทอร์เน็ต และมีปุ่มเปิดไฟล์ (BIM: ผลคำนวณจาก MEP และ เชื่อมกับโครงการใน PENUM MEP)

คีย์อื่นเป็นของโปรแกรมเดียว เช่น `penum.pm.*` (PM), `hvac-*`, `penum.mep.sent` (MEP), `penum.snaps`, `penum.sharedparams`, `penum.bim.link` (BIM)
ยกเว้น `penum.fb.draft`, `penum.fb.contact` ที่กล่องแจ้งปัญหาใช้ร่วมกัน และ `penum.revoked`, `penum.plans`, `penum.licences.first`
ที่รหัสเปิดใช้งานใช้ร่วมกัน

- เปิดไฟล์: ดับเบิลคลิกไฟล์ `.penmep` (PENUM MEP ที่ติดตั้งเป็นแอปบน Chrome/Edge คอมพิวเตอร์) ลากไฟล์มาวางในหน้า หรือ เมนู › เปิดไฟล์โครงการ

  หน้าต่างอื่นเขียน `hvac-load-v1` ทับ หน้านี้เตือนครั้งเดียว โครงการที่ซ้ำอยู่แล้ว (ชื่อ ห้อง พื้นที่ TR BOQ เท่ากัน) มีปุ่ม "รวมเป็นอันเดียว" เก็บอันที่เปิดอยู่ (หรือแก้ล่าสุด)
  ใช้รหัสเชื่อมที่ PM/BIM ในเครื่องนี้หรือคลาวด์ใช้อยู่ อันอื่นไปถังขยะ เลิกทำได้

## บันทึกลงเครื่องใน PENUM PM (3.88) และ PENUM BIM (V1.72)

ใช้ `shared/files.js` เหมือน MEP: เลือกโฟลเดอร์ครั้งเดียว บันทึกโครงการเดิมซ้ำจะเขียนทับเฉพาะไฟล์ของโครงการนั้น ไฟล์อื่นในโฟลเดอร์ไม่ถูกแตะ
เบราว์เซอร์ที่เลือกโฟลเดอร์ไม่ได้ (มือถือ Safari Firefox) ดาวน์โหลดแทน `penumFiles.init(app, {sub, avoid})` เปลี่ยนชื่อโฟลเดอร์และห้ามโฟลเดอร์บางที่ได้

- PM (`pm/src/925-save-files.js`): เมนู › บันทึกโครงการนี้ลงเครื่อง / บันทึกทุกโครงการลงเครื่อง เขียน `<ชื่อโครงการ>.penpm`
  (`{fmt:'penum-pm', projects:{id: โครงการ}, photos}` 1 โครงการต่อไฟล์) ในโฟลเดอร์ `PENUM-PM-FILES` ไม่ใช้ชื่อ PENUM-PM
  เพราะโฟลเดอร์ข้อมูลบริษัทที่ซิงค์ (OneDrive) ต้องมีแต่ข้อมูลบริษัท เลือกโฟลเดอร์ PENUM-PM หรือโฟลเดอร์ที่มี `penum-pm.json` จะถูกปฏิเสธ
  เปิดไฟล์: เมนู › เปิดไฟล์โครงการ (.penpm) ดับเบิลคลิก ลากมาวาง (`window.pmFileIn(txt, name)` ไฟล์ `.penmep` ส่งต่อให้ `pmMepFile`)
  โครงการที่มีอยู่แล้ว (id เดียวกัน) ถามก่อน: แทนที่ (↶ ย้อนกลับได้) หรือเก็บไว้ทั้งสองอัน (id ใหม่ ชื่อ "(จากไฟล์)")
  เฉพาะผู้ดูแลระบบเมื่อเปิดใช้ PIN (เหมือนสำรองข้อมูล) และเปิดไฟล์เข้าไม่ได้เมื่อสิทธิ์หมดอายุ
- BIM: ไฟล์ › บันทึกลงเครื่อง (.penbim) หรือ Ctrl+S เขียน `<ชื่อโครงการ>.penbim` (ข้อมูลเดียวกับไฟล์ .json เดิม) ในโฟลเดอร์ `PENUM-BIM`
  ไฟล์ของโครงการเดียวกันดูจาก `guid` ไฟล์ › เปิดไฟล์งาน… แสดงไฟล์ในโฟลเดอร์ก่อน ยังเปิด `.json` เดิมได้ เปิดไฟล์แทนโครงการที่มีงานอยู่
  จะถามก่อน (บันทึกโครงการที่เปิดอยู่ก่อนได้) และ Ctrl+Z ย้อนกลับไปโครงการเดิมได้

## หน้าเริ่มต้น MEP (v120) และ BIM (V1.73)

เปิดโปรแกรมแล้วเจอหน้าเริ่มต้นก่อน แบบ AutoCAD: การ์ดใหญ่ "ทำต่อ: <โครงการล่าสุด>" (Enter หรือ Esc = ทำต่อ), โครงการใหม่, เปิดไฟล์,
รายการล่าสุด และงานตัวอย่าง หน้านี้เป็นชั้นบนหน้าโปรแกรม โครงการที่เปิดอยู่ไม่ถูกเปลี่ยนจนกว่าจะเลือก

- แสดงครั้งเดียวต่อหน้าต่าง (`sessionStorage` `mep-started` / `bim-started`) รีโหลดหรือกดอัปเดตโปรแกรมจึงทำงานต่อเลย
  ไม่แสดงเมื่อเปิดด้วยการดับเบิลคลิกไฟล์ (`launchQueue`), ใน iframe และ MEP ลิงก์ `#v3d=`
- MEP (`pjsShow`): รายการล่าสุดมาจาก `pjRows()` (IndexedDB `penum-mep`) 8 โครงการ งานตัวอย่างอยู่ในหัวข้อพับได้ (`preCard()`)
  โครงการตัวอย่าง (`P.smp===1`) ไม่ขึ้นเป็นการ์ดทำต่อ
- BIM (`bsShow`): รายการล่าสุดคือไฟล์ `.penbim` ในโฟลเดอร์ `PENUM-BIM` (`penumFiles.list`) ถ้าเบราว์เซอร์ยังไม่ให้สิทธิ์โฟลเดอร์จะมีปุ่มขอสิทธิ์
  บ้านตัวอย่าง (`mlSample()`) ไม่ขึ้นเป็นการ์ดทำต่อ เริ่มใหม่หรือเปิดไฟล์แทนโครงการที่มีงานอยู่จะถามก่อน (บันทึกก่อนได้)

## โครงการของบริษัท (MEP v125, BIM V1.74; ผู้ใช้งาน MEP v126, BIM V1.75)

พนักงานบริษัทเดียวกันเห็นโครงการ MEP และ BIM ของกันและกัน ไม่ว่าทำที่เครื่องไหน รู้ว่าใครบันทึกล่าสุด และใครกำลังแก้อยู่ ไม่แก้ทับกัน
(`shared/team.js`, app.json `"team": true`, ตาราง Supabase `tools/team-setup.sql` รันครั้งเดียว)

- บริษัท = รหัสเปิดใช้งาน (`penumLic.state().code` และ `.cid` รหัสลูกค้า) เครื่องที่ถือรหัสของบริษัทหาแถว `penum_team_key` ด้วย
  sha256('penum-team-c:' + รหัส) 16 ไบต์แรก ข้างในคือกุญแจของบริษัท (สุ่มโดยเครื่องแรก เข้ารหัสด้วย sha256('penum-team-ck:' + รหัส))
  แถวโครงการ `penum_team` หาด้วย sha256('penum-team:' + กุญแจ) และเข้ารหัส AES-GCM ด้วย sha256('penum-team-key:' + กุญแจ) ORIEN อ่านไม่ได้
  รหัสที่ต่ออายุ (รหัสใหม่) ได้กุญแจเดิมจากเครื่องที่เคยรู้ (`penum.team` › `co[รหัสลูกค้า]`) จึงเป็นรายการเดิม
- แถวหนึ่ง = โครงการหนึ่ง: `p` = sha256('penum-team-p:' + โปรแกรม + ':' + รหัสโครงการ) (MEP ใช้ `P.lid`, BIM ใช้ `P.guid`), `m` = สิ่งที่รายการแสดง
  (ชื่อ ลูกค้า เลขที่ ตัวเลขสรุป ผู้บันทึก), `d` = ตัวโครงการ (MEP ไม่รวม `pid` ซึ่งเป็นของแต่ละเบราว์เซอร์), `at` = ฉบับ, `off` = เอาออกจากรายการ
- ส่งขึ้น: โครงการที่เปิดอยู่ 6 วินาทีหลังแก้ไข และก่อนเปิดโครงการอื่น (MEP) MEP ส่งโครงการอื่นในรายการของเครื่องขึ้นครั้งเดียว (เมื่อรายการของบริษัทยังไม่มี)
  ไม่ส่ง: โครงการตัวอย่างที่ยังไม่แก้ บ้านตัวอย่าง โครงการว่าง โหมดอ่านอย่างเดียว และโครงการที่ใหญ่เกิน 3 MB หลังบีบอัด
- ล็อกการแก้: เครื่องที่เปิดโครงการอยู่ยืนยันทุก 50 วินาที (`penum_team_lock`) หมดเมื่อไม่ยืนยัน 150 วินาที ปิดหน้า หรือไม่ได้ใช้ 15 นาที
  เครื่องอื่นเปิดดูได้ (แถบด้านล่าง "… กำลังแก้โครงการนี้อยู่") การแก้ในเครื่องนั้นไม่ส่งขึ้น มีปุ่ม ทำสำเนาเป็นงานของฉัน และ แก้แทน
  เซิร์ฟเวอร์ไม่รับการบันทึกที่ไม่ได้เริ่มจากฉบับล่าสุด (`p_base`) เครื่องที่แก้ไปด้วยจะถาม: ใช้ฉบับล่าสุด (ของตัวเองเก็บเป็นสำเนา: MEP อีกโครงการในรายการ
  BIM ไฟล์ .penbim) หรือ ส่งของตัวเองทับ ถ้าเครื่องนี้ไม่ได้แก้ ฉบับล่าสุดแทนที่ให้เอง (BIM กด Ctrl+Z กลับได้)
- `penum.team` (localStorage ใช้ร่วม MEP/BIM): `dev` เลขเครื่องสุ่ม, `name` ชื่อที่เพื่อนร่วมงานเห็น, `sid` รหัสพนักงานใน PM ที่เลือก,
  `asked` ถามชื่อแล้ว, `co` กุญแจบริษัท, `s` ฉบับที่เครื่องนี้ส่ง/รับล่าสุดต่อโครงการ
- ผู้ใช้งาน (v126 / V1.75): ปุ่มไอคอนคน + ชื่อบนหัวจอ ข้างปุ่มเมนู (`penumTeam.chip()`) แบบช่องผู้ใช้ของ PENUM PM กดแล้วเลือกชื่อจาก
  รายชื่อพนักงานของ PM หรือพิมพ์ชื่อ ชื่อที่ใช้: `penum.team.name` ก่อน ถ้าไม่มี ใช้คนที่ใช้งาน PM ในเบราว์เซอร์นี้อยู่ (อ่านอย่างเดียว:
  `penum.pm.v1[.cN]` บริษัทที่ `co.lic` เป็นลูกค้าเดียวกับรหัสของ MEP/BIM ก่อน แล้วบริษัทที่ PM เปิดอยู่ ข้ามบริษัทอื่น;
  คนใน `penum.pm.auth` เมื่อเปิด PIN ไม่งั้น `penum.pm.ui.me`) ยังไม่มีชื่อ ปุ่มเป็นสีส้ม "ใส่ชื่อผู้ใช้" และถามเองครั้งเดียวเมื่อรายการของบริษัทใช้ได้
  มือถือแสดงแค่ไอคอน
- ที่อยู่ในโปรแกรม: MEP หน้าโครงการทั้งหมด (การ์ดบนสุด) และหน้าเริ่มต้น, BIM หน้าเริ่มต้น และ เมนู › โครงการของบริษัท
  เปิดโครงการที่มีในเครื่องอยู่แล้ว (รหัสเดียวกัน) เปิดฉบับในเครื่อง แล้วเทียบกับของบริษัทตามข้างบน

## รหัสเปิดใช้งาน

ORIEN ออกรหัสที่โปรแกรม ORIEN ฝ่ายขาย (`sales/`) บริษัทลูกค้าละ 1 รหัส รหัสบอกว่าเปิดโปรแกรมไหนได้ในช่อง `ap`
(`["pm"]`, `["mep","bim"]`, `["pm","mep","bim"]` …) รหัสเก่าที่ไม่มี `ap` คือ PENUM PM อย่างเดียว ราคาคิดจาก `pm/files/plans.json`
(`plans` = แพ็กเกจ PM, `apps` = ราคา MEP และ BIM, `bundle.off` = ส่วนลดเมื่อเช่าครบ 3 โปรแกรม)

รหัสคือ `PNM1.<payload>.<ลายเซ็น>` เซ็นด้วย ECDSA P-256 โปรแกรมตรวจด้วยกุญแจสาธารณะอย่างเดียว ซึ่งต้องตรงกันใน
`shared/licence.js`, `pm/src/810-licence.js` และ `sales/index.html` (`check-apps` ตรวจให้) **กุญแจส่วนตัวห้ามขึ้น GitHub หรือเว็บเด็ดขาด**
payload ยังเป็น `v:1` เพื่อให้ PM รุ่นเก่ารับรหัสแพ็กรวมได้ เพิ่มช่องใหม่ได้ แต่ห้ามเปลี่ยนความหมายของช่องเดิม

- PENUM PM เก็บรหัสไว้กับข้อมูลบริษัท (`DB.co.lic`) รับเฉพาะรหัสที่มี `pm` และเขียนรหัสของบริษัทลง `penum.licences`
  ทุกครั้งที่เปิด เครื่องที่ใช้ PM ของบริษัทจึงเปิด MEP และ BIM ที่อยู่ในรหัสได้เลย ไม่ต้องใส่รหัสซ้ำ
- PENUM MEP และ BIM (`shared/licence.js` ที่ `build-pages` ใส่ไว้ใน `<head>`) อ่านรหัสจาก `penum.licences`
  - เครื่องที่ยังไม่มีรหัสของโปรแกรมนี้ เห็นหน้าใส่รหัสก่อนใช้งาน (ใส่รหัสหรือเปิดลิงก์ `…/mep/#lic=<รหัส>`)
  - เครื่องที่มีงานของโปรแกรมนั้นอยู่แล้วตอนได้รุ่นนี้ครั้งแรก (เครื่องของ ORIEN เอง) ใช้ต่อได้ฟรี บันทึกไว้ใน `penum.licences.first`
  - เหลือไม่ถึง 30 วันมีแถบเตือน หมดอายุแล้วใช้ต่อได้ 7 วัน จากนั้นหรือเมื่อรหัสถูกยกเลิก เปิดดูและพิมพ์ได้อย่างเดียว
    (ไม่บันทึกคีย์ใน `licence.keys` และช่องพิมพ์ถูกล็อก งานเดิมไม่ถูกลบ)
  - เมนู › สิทธิ์การใช้งาน แสดงรหัสที่ใช้อยู่และใส่รหัสใหม่ได้
- ต่ออายุหรือเพิ่มโปรแกรม: ORIEN ออกรหัสใหม่ (รหัสลูกค้าเดิม) แล้วฝ่ายขายส่งเข้า Supabase ของ ORIEN เอง (ปุ่ม อนุมัติและส่งให้ลูกค้า /
  ส่งให้ลูกค้าอัตโนมัติ: ตาราง `penum_lic_renew` เขียนผ่าน rpc `penum_lic_put` ด้วยรหัส ORIEN ตัวเดียวกับกล่องรับเรื่อง อ่านผ่าน
  `penum_lic_get` ด้วยกุญแจสาธารณะ ตั้งค่าครั้งเดียวด้วย `tools/licence-setup.sql`) หรือ Claude ประกาศใน `pm/files/licences.json`
  แบบเดิม ทั้งสองที่เข้ารหัสด้วยรหัสเดิม PM, MEP และ BIM ดึงรหัสใหม่เองเมื่อเปิด หรือกลับมาที่หน้าต่าง (ไม่เกินทุก 30 นาที) ตอนต่อเน็ต
  ลูกค้าไม่ต้องใส่รหัสใหม่ ยกเลิกรหัส: `pm/files/revoked.json` ใช้กติกาเดียวกันทุกโปรแกรม
- ตรวจทั้งหมดในเบราว์เซอร์ คนที่แก้โค้ดในเครื่องตัวเองข้ามได้ จุดประสงค์คือให้ลูกค้าที่ซื่อสัตย์ใช้ถูกแพ็กเกจ ไม่ใช่กันคนเจาะ
- แนะนำโปรแกรมที่ยังไม่ได้เช่า (MEP v118, BIM V1.71, PM 3.86): ตรงที่เชื่อมกับอีกโปรแกรม ถ้าบริษัทยังไม่ได้เช่าโปรแกรมนั้นจะมีกล่อง
  บอกว่าโปรแกรมนั้นช่วยอะไร ราคาเริ่มต้น และปุ่ม "ขอเพิ่ม …" (MEP: การ์ดส่ง BOQ ให้ PM และการ์ดเชื่อมต่อกับ BIM;
  BIM: ผลคำนวณจาก MEP และกล่องเชื่อมรหัส; PM: หน้า ข้อมูลโครงการและ BOQ เมื่อยังไม่ได้เชื่อม)
  - `penumLic.has(app)` (`shared/licence.js`): `true` เมื่อรหัสในเครื่องเปิดโปรแกรมนั้น ใช้ฟรีใน `penum.licences.first` หรือ (PM)
    เครื่องนี้มีบริษัทใน PENUM PM แล้ว, `false` เมื่อรหัสในเครื่องไม่มีโปรแกรมนั้น, `null` เมื่อโปรแกรมที่เปิดอยู่ใช้ฟรีในเครื่องนี้หรือยังไม่มีรหัส กล่องแสดงเฉพาะเมื่อเป็น `false`
  - `penumLic.upsell(app)` ให้ HTML ของกล่อง `penumLic.ask(app)` เปิดหน้าต่างขอเพิ่ม (LINE, อีเมล หรือกล่องแจ้งปัญหา) ข้อความลงท้ายด้วย
    `[PENUM-PLAN] <รหัสลูกค้า> <เลขรหัส> <แพ็กเกจ>><แพ็กเกจ> +<app>` ที่ ORIEN ฝ่ายขายอ่านเป็น "ขอเพิ่มโปรแกรม"
  - PM ใช้กล่องของตัวเอง (`mepUp` ใน `pm/src/920-mep-link.js`): ผู้ดูแลระบบได้ปุ่มขอเปลี่ยนแพ็กเกจที่ติ๊ก PENUM MEP ไว้ให้ คนอื่นได้ข้อความให้แจ้งผู้ดูแล

## หน้าต่างแยกต่อโปรแกรม

ปุ่ม PENUM PM / MEP / BIM เปิดอีกโปรแกรมในหน้าต่างชื่อ `penum-pm`, `penum-mep`, `penum-bim`
กดซ้ำจะเรียกหน้าต่างเดิมขึ้นมาโดยไม่โหลดใหม่ จึงวางแต่ละโปรแกรมไว้คนละจอได้ (MEP/BIM: `goApp()`, PM: ลิงก์ `target="penum-…"`)

## คำสั่ง

- สร้างทั้งเว็บ: `node tools/build-pages.mjs site`
- สร้างเฉพาะโปรแกรมเดียว: `node tools/build-pages.mjs site pm` (ได้ `site/pm/` กับ `site/icons/`)
- ตรวจ: `node tools/check-apps.mjs` หรือ `node tools/check-apps.mjs mep` ตรวจว่าสคริปต์ทุกก้อน parse ได้, เจอเลขรุ่น,
  คีย์เชื่อมข้อมูลและปุ่มเปิดหน้าต่างยังอยู่ครบตาม app.json, กล่องแจ้งปัญหาตรงกับ `shared/feedback.js`,
  คีย์ใน `licence` ยังอยู่ในซอร์ส และกุญแจสาธารณะของรหัสตรงกันทุกโปรแกรม
  รันอัตโนมัติทุก pull request (`.github/workflows/check.yml`) และก่อนขึ้นเว็บทุกครั้ง (`pages.yml`)
- แก้กล่องแจ้งปัญหา: แก้ `shared/feedback.js` แล้วรัน `node tools/sync-feedback.mjs` (สำหรับ PM จะเขียนลง `pm/src/992-feedback.html`)
- PM แบบไฟล์ย่อย: `node tools/src.mjs join pm` (หน้าเต็ม), `split pm <ไฟล์>` (ตัดหน้าเต็มกลับเป็นไฟล์ย่อย), `where pm <บรรทัด>` (บรรทัดในเบราว์เซอร์อยู่ไฟล์ไหน)

## กติกาการพัฒนา

- งานหนึ่งชิ้นแก้โปรแกรมเดียวเท่าที่ทำได้ งานที่ต้องแก้หลายโปรแกรมให้บอกไว้ใน PR
- PM แก้ใน `pm/src/` เท่านั้น อย่าสร้าง `pm/index.html` กลับมา (ถูก .gitignore ไว้ และการสร้างเว็บไม่ใช้)
- เปลี่ยนรูปแบบข้อมูลใน `penum.mep.link` ได้เฉพาะเพิ่มช่อง ถ้าต้องเปลี่ยนความหมายให้เพิ่ม `fmt` และให้ผู้อ่านรองรับทั้งสองแบบ
- ห้ามเปลี่ยนที่อยู่ `/penum/<app>/`, id ของ manifest (`/penum/<app>/`) และคีย์ข้างบน เพราะแอปที่ติดตั้งและข้อมูลลูกค้าผูกอยู่
- MEP หรือ BIM เปลี่ยนชื่อคีย์ที่บันทึกงาน ต้องแก้ `licence.keys` / `licence.work` ใน app.json ด้วย (`check-apps` เตือนถ้าคีย์หายจากซอร์ส)
